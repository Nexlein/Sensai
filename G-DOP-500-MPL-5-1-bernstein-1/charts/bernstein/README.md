# charts/bernstein

Helm chart deploying the whole application: `poll`, `worker`, `result`, Redis and PostgreSQL. Why Helm rather than Kustomize or raw manifests is recorded in [ADR-0001](../../docs/adr/0001-deployment-stack.md); every file of the chart is explained in [docs/helm-chart.md](../../docs/helm-chart.md).

## Usage

`global.registry`, `global.tag` and the PostgreSQL password are required:

```sh
export POSTGRES_PASSWORD="$(openssl rand -base64 32)"   # or your own long password

helm upgrade --install bernstein charts/bernstein \
  --namespace bernstein --create-namespace \
  --atomic --wait --timeout 10m \
  --set global.registry=bernsteinacr.azurecr.io \
  --set-string global.tag=<git-sha> \
  --set-string postgres.password="$POSTGRES_PASSWORD"
```

- `global.tag` is the SHA tag CI pushed to the registry. Use `--set-string` for it: an all-digit short SHA passed with `--set` becomes a number and is rejected by the schema.
- The PostgreSQL password is never written in a file: it comes from the environment. To use a Secret you created instead, set `postgres.existingSecret` ([docs/postgres.md](../../docs/postgres.md#password)). The Redis password is generated by the chart ([docs/redis.md](../../docs/redis.md#password)).
- `--atomic` rolls the release back automatically if it does not become healthy before the timeout.
- `helm history bernstein -n bernstein` lists the revisions, and `helm rollback bernstein <revision> -n bernstein` goes back to one.

Without these values, `helm install`, `helm template` and `helm lint` stop before touching the cluster:

```text
Error: INSTALLATION FAILED: values don't meet the specifications of the schema(s) in the following chart(s):
bernstein:
- at '/global/registry': minLength: got 0, want 1
```

```text
Error: INSTALLATION FAILED: execution error at (bernstein/templates/postgres/secret.yaml:10:15): postgres.password is required: pass --set-string postgres.password="$POSTGRES_PASSWORD", or set postgres.existingSecret
```

Check the chart locally:

```sh
OK="--set global.registry=example.azurecr.io --set-string global.tag=dev --set-string postgres.password=dev"
helm lint charts/bernstein $OK
helm template bernstein charts/bernstein $OK
```

## Values

Every key is documented in [`values.yaml`](values.yaml); types and required keys are enforced by [`values.schema.json`](values.schema.json).

| Key | Default | Description |
|---|---|---|
| `global.registry` | `""` (required) | Registry of the poll, worker and result images, e.g. `bernsteinacr.azurecr.io` |
| `global.tag` | `""` (required) | Image tag of poll, worker and result: the git SHA built by CI |
| `global.imagePullPolicy` | `IfNotPresent` | Pull policy of every container |
| `<component>.image.registry` | `global.registry` | Overrides the registry of one component |
| `<component>.image.repository` | `poll`, `worker`, `result`, `library/redis`, `library/postgres` | Image name inside the registry |
| `<component>.image.tag` | `global.tag` | Overrides the tag of one component |
| `<component>.image.digest` | `""` | `sha256:...` pinning the exact image |
| `worker.replicas` | `2` | Number of worker pods |
| `worker.resources` | requests 50m / 128Mi, limit 256Mi | CPU and memory of the worker container |
| `postgres.database` | `votes` | Database used by worker and result |
| `postgres.user` | `bernstein` | Owner of that database |
| `postgres.password` | `""` (required) | Its password, given at deploy time; stored in the Secret `postgres-credentials` |
| `postgres.existingSecret` | `""` | Secret with a `password` key to use instead of `postgres.password` |
| `postgres.persistence.storageClass` | `managed-csi` | StorageClass of the data disk; `""` for the cluster's default |
| `postgres.persistence.size` | `5Gi` | Data disk size, fixed at the first install |
| `postgres.resources` | requests 100m / 256Mi, limit 512Mi | CPU and memory of the PostgreSQL container |
| `redis.existingSecret` | `""` | Secret with a `password` key; empty: generated once in `redis-credentials` |

Redis and PostgreSQL use the official Docker Hub images (`redis:8`, `postgres:18.6` pinned by digest), as required by the application.

## Layout

```
charts/bernstein/
├── Chart.yaml
├── values.yaml           # documented defaults
├── values.schema.json    # fails fast on missing or malformed values
└── templates/
    ├── _helpers.tpl      # labels, image and secret helpers
    ├── NOTES.txt         # printed after install: how to reach poll and result
    ├── poll/
    ├── worker/
    ├── result/
    ├── redis/
    │   └── secret.yaml   # generated Redis password
    └── postgres/
        ├── secret.yaml       # PostgreSQL password from the deploy
        ├── statefulset.yaml  # PostgreSQL 18 and its data disk
        └── service.yaml      # postgres:5432 + headless Service
```

Each component's manifests go in its own folder, named like its key in `values.yaml`.

## Writing templates

Every helper takes the root context and the component name (syntax and line-by-line explanation in [docs/helm-helpers.md](../../docs/helm-helpers.md)):

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: poll
  labels:
    {{- include "bernstein.labels" (dict "context" $ "component" "poll") | nindent 4 }}
spec:
  selector:
    matchLabels:
      {{- include "bernstein.selectorLabels" (dict "context" $ "component" "poll") | nindent 6 }}
  template:
    metadata:
      labels:
        {{- include "bernstein.labels" (dict "context" $ "component" "poll") | nindent 8 }}
      annotations:
        checksum/redis-secret: {{ include "bernstein.secretChecksum" (dict "context" $ "component" "redis") }}
    spec:
      containers:
        - name: poll
          image: {{ include "bernstein.image" (dict "context" $ "component" "poll") }}
          imagePullPolicy: {{ .Values.global.imagePullPolicy }}
          env:
            - name: REDIS_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: {{ include "bernstein.secretName" (dict "context" $ "component" "redis") }}
                  key: password
```

| Helper | Output |
|---|---|
| `bernstein.labels` | `helm.sh/chart`, `app.kubernetes.io/{name,instance,component,version,managed-by}`. Put it on **every** object and pod template. |
| `bernstein.selectorLabels` | `app.kubernetes.io/{name,instance,component}` only, for `selector`s and Services. Selectors are immutable, so they never include the version. |
| `bernstein.image` | `<registry>/<repository>:<tag>[@<digest>]` from `<component>.image`, defaulting to `global.registry` and `global.tag`. |
| `bernstein.secretName` | Name of the Secret holding a component's password (`postgres`, `redis`). Use it in every `secretKeyRef`. |
| `bernstein.secretChecksum` | Fingerprint of that password. Put it in a `checksum/<component>-secret` annotation of every pod template reading the password, so a new password restarts the pods. |
| `bernstein.env.redis` | `REDIS_HOST` and `REDIS_PASSWORD` env entries (poll, worker). Takes `(dict "context" $)` only. |
| `bernstein.env.postgres` | `POSTGRES_*` env entries (worker, result). Takes `(dict "context" $)` only. |

For the secret helpers, pass the component that **owns** the password: poll and the worker read `redis`, the worker and result read `postgres`.

`app.kubernetes.io/version` is the tag the component actually runs: `global.tag` for poll, worker and result, `8` for Redis, `18` for PostgreSQL.

When adding values, document each key in `values.yaml` and add it to `values.schema.json`.
