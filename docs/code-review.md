# Code review

Review of the whole code base (`src/sensai`, about 7 500 lines, and `tests/`) on 2026-10-21,
branch `feat/benchmarks-config-docs`. Numbers come from the [benchmarks](benchmarks.md).

**Verdict**: a clean, well-layered code base with unusually careful edge-case handling
(guardrails, cancellation, MCP failures). Its weak points were operational rather than
structural: a context-window mismatch that silently cut prompts, a slow vector search, and
a hand-written config writer. Those are fixed in this branch; what remains is listed by
priority at the end.

## What is good

| Area             | Why it is good                                                                                                                                                                                                                                                                                                                                                            |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Architecture     | Strict one-way layering. `domain/protocols.py` is a real seam: the engine never imports a concrete provider, store or guardrail, and `core/bootstrap.py` is the single wiring point shared by CLI, TUI and web. Swapping Ollama for the mock in tests needs no patching.                                                                                                  |
| Streaming engine | The turn is split into small, single-purpose classes (`ChatEngine`, `RoundStream`, `ToolRunner`, `PromptComposer`, `Turn`/`Round`). Events are typed pydantic models, so the three UIs render the same stream.                                                                                                                                                            |
| Failure handling | Provider errors are wrapped once into `ProviderError` and worded in one line (`interfaces/notices.py`). A cancelled or failed turn rolls back the unanswered user message (`ChatEngine.send`). A broken confirmation callback never authorizes a tool. A failing MCP server is skipped with a warning.                                                                    |
| Guardrails       | Regex plus real checksums (Luhn, IBAN mod 97, NIR key) so random numbers are not masked; bounded quantifiers against catastrophic backtracking (tested on hostile input); the streaming filter never shows half a value; findings carry the rule name, never the value. An adversarial corpus documents known gaps instead of hiding them. Cost: about 35 µs per message. |
| Tool safety      | File tools resolve paths and reject traversal, symlinks included. Sensitive tools always ask, with a full diff (`write_file`) or the full code (`run_python`). The sandbox drops network, capabilities and root, caps memory, CPU, PIDs and time, and kills the container on timeout.                                                                                     |
| MCP client       | A small, correct JSON-RPC-over-stdio client: handshake, request ids, notifications skipped, 16 MiB lines, stderr discarded so the server never blocks, clean shutdown.                                                                                                                                                                                                    |
| Observability    | `/prompt` shows the exact prompt with the source of every message; `[eval] log_prompts` logs it even when the call fails; real token counts and rates come from Ollama's counters.                                                                                                                                                                                        |
| Tests            | 1 250 fast tests (about 25 s), mirroring the source tree, with fakes at the protocol seam and opt-in live tests against a real model, Docker and GitHub.                                                                                                                                                                                                                  |
| Docs             | Deep feature write-ups (MCP, sandbox) that explain the why, not only the how.                                                                                                                                                                                                                                                                                             |

## What was wrong, fixed in this branch

| Severity | Problem                                                                                                                                                                                                                                                                                                                                                                                                         | Fix                                                                                                                                                                                                                                                               |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| High     | **Silent prompt truncation.** The budget assumed 8 192 tokens but nothing told Ollama, whose own window is 4 096 tokens on a machine without a GPU. Prompts between 4 096 and 8 192 tokens lost their beginning, which holds the persona and system notes, with no error. Measured: a 6 000-token prompt is cut to 4 096 and the fact at its start is lost ([benchmarks](benchmarks.md#context-window-limits)). | `options.num_ctx` now defaults to 8 192 (kept when an `[options]` table omits it), so the window always matches the budget.                                                                                                                                       |
| High     | **Settings could not really be changed live.** `/config set` knew 9 keys; saving rewrote the whole file by hand, section by section, dropping comments, and each new section had to be added to the writer or it would be deleted on save.                                                                                                                                                                      | Generic settings layer: every key settable, validated against the whole config, applied live where possible, saved per key with comments kept, `/config reset`, `/config keys`, `sensai config` in the shell, autosave. See [configuration.md](configuration.md). |
| Medium   | **RAG search cost grew fast**: every query JSON-decoded every stored vector and computed cosine in pure Python, then built a pydantic object per chunk. 232 ms per question for 1 000 chunks.                                                                                                                                                                                                                   | Vectors stored as packed doubles, scored with a C dot product, only the top K are fetched in full: 7 to 8× faster with identical results (old JSON indexes still read).                                                                                           |
| Medium   | **Slow start-up**: the CLI imported the TUI (Textual) and the web stack (FastAPI, uvicorn) even when unused. 398 ms to import the entry point.                                                                                                                                                                                                                                                                  | Both are imported when chosen: 216 ms.                                                                                                                                                                                                                            |
| Medium   | `requires-python = ">=3.10"` while the code uses `tomllib` and `datetime.UTC`, both 3.11+: installing on 3.10 succeeded and then crashed at import.                                                                                                                                                                                                                                                             | `requires-python = ">=3.11"`.                                                                                                                                                                                                                                     |
| Low      | Test output was dots; the jury asked for "more than OK".                                                                                                                                                                                                                                                                                                                                                        | Every test printed by title with its result, per-area summary, Markdown report ([testing.md](testing.md)).                                                                                                                                                        |
| Low      | Stale docs: `architecture.md` listed the sandbox, web UI and evaluator as stubs; `memory.md` linked to a teammate's home directory.                                                                                                                                                                                                                                                                             | Docs rewritten and reorganized.                                                                                                                                                                                                                                   |

## Style

Consistent naming, small functions, docstrings that say why rather than what, and almost no
broad `except` outside the places that must never crash (tool runner, previews). Ruff lint and
format run in pre-commit and CI. One habit to keep an eye on: some modules mix several
concerns (`core/commands.py` holds every command; it would split naturally into one module per
command group).
